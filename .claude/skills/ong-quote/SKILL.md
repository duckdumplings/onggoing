사용자가 `/ong-quote` 뒤에 물류 정보나 변경 요청을 붙이면 이 저장소의 결정론적 계산기로 견적을 만든다. 먼저 `docs/team-quote-guide.md`를 읽고 JSON 필드나 예시가 필요하면 `src/domains/quote/team/input.ts`와 `examples/team-quote.example.json`을 확인한다.

## 입력 해석

- 원본의 상차지·배송지·반납지, 배송 마감, 기업 수, 가방 수, 기업별 전달, 맞수거를 분리한다. 같은 주소라도 기업별 전달이면 `recipients`에 모두 기록한다. 상품 행이 나뉜 동일 배송지는 합치되 가방 수는 합산한다.
- 명시된 날짜와 차종을 사용한다. 운행일 또는 차종이 없으면 먼저 확인한다. "금요일 기준"만 주어졌다면 계산할 실제 금요일 날짜를 명시해 가정하고 진행할 수 있다.
- "상차지 중 한 곳을 가산으로 변경"처럼 대상이 불명확하면 후보별 `cases`를 만든다. 가산 상차지 기본주소는 서울 금천구 가산디지털1로 70이고, 가산 반납지는 서울 금천구 가마산로 96이다. 두 주소를 혼동하지 않는다.
- `pickupStart`는 첫 상차 작업 시작시각이다. 상차를 앞당길 수 있다는 근거가 있으면 여유 있게 제안하고 `assumptions`에 기록한다. 원본 음식 준비시각 `readyAt`은 임의로 앞당기지 않는다.
- 배송시각은 전달 완료 마감이다. 최대 15분 조기 배송, 기본 20분 안전버퍼를 적용한다. 기업별 전달·주차·엘리베이터 작업시간을 포함한다. 맞수거는 `collection`으로 별도 기록하며 원본 12:31 같은 수거 가능시각도 보존한다.
- 기존 가격은 `baseline`에 부가세 포함 여부를 함께 기록한다. 여부를 모르면 `unknown`으로 두고 동일 기준 증액으로 단정하지 않는다. 전화번호·출입 비밀번호는 계산에 불필요하므로 JSON에 복사하지 않는다.

## 계산과 전달

1. 입력을 `quote-runs/<이름>.json`에 저장하고 `npm run quote:team -- quote-runs/<이름>.json --check`로 검증한다. 기본값과 가정을 짧게 설명한다. 꼭 필요한 정보가 빠진 경우에만 질문하고, 확인받은 정보는 다시 묻지 않는다.
2. 검증되면 같은 명령에서 `--check`를 빼고 실행한다. 서버는 자동 준비된다. 공개 예제의 주소는 가상이므로 실제 도로 조회에 사용하지 않는다. 키가 없으면 가이드의 팀원 초기 설정을 안내한다. 필요한 설정은 Tmap 키·Supabase URL·공개 접근 키뿐이며 관리자 키나 별도 LLM API 키는 필요 없다. 키를 대화에 붙이도록 요청하거나 문서·커밋·결과물에 넣지 않는다. 소유자용 `quote:team:export-env`는 사용자가 설정 파일 공유 준비를 요청한 경우에만 실행한다.
3. 생성된 Markdown의 금액·시간·거리·배송 상태를 근거로 안내한다. 기존 가격 비교, 버퍼 포함 총운행시간과 청구시간, 교통 및 운임표 근거, 가정과 확인할 항목을 함께 전한다. 생성된 `.md`와 `.result.json` 경로도 제공한다.
4. 마감 미충족은 그대로 알린다. 조정안을 검토할 때는 별도 case를 만들고 어떤 마감·준비시각·순서를 바꿨는지 표시한다. 원본 마감은 유지하며, 사용자가 수락하기 전에는 조정안으로 운영 가능하다고 확정하지 않는다.

운임은 운행일이 아닌 계산 시점 유효 운임표를 사용하므로 보고서의 `effectiveFrom`과 출처를 함께 확인한다. 운임표 기본값 사용 또는 교통 fallback은 **참고 견적**으로 설명한다. 안전버퍼 검증은 시뮬레이션이며 정시 배송을 보증하지 않는다. 실제 기사·차량 가용성, 시작 가능일, 적재 가능 여부는 운영팀 확인 사항이다. 계산은 고객 발송·배차 확정·코드 배포 권한을 포함하지 않는다.
