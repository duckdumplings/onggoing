# 팀 배송라인 견적 사용법

팀원 PC에 아래 공유용 버전을 내려받고 초기 설정을 한 번 마치면, Claude Code에서 `/ong-quote` 뒤에 고객이 준 표·CSV·메모를 그대로 붙이면 된다. Claude가 주소와 시간 의미를 정리하고 같은 계산기로 견적 안내문을 만든다. 팀원이 직접 JSON이나 서버를 다룰 필요는 없다. 스킬 파일 하나가 아니라 이 프로젝트 전체가 필요하다.

```text
/ong-quote
다음 금요일 기준, 레이 차량으로 견적 내줘.
배송 마감은 꼭 지키고 최대 15분 조기 배송, 안전버퍼 20분.
상차 시작은 앞당겨도 되지만 음식 준비시각은 원문대로 유지해줘.
부가세 제외 금액, 버퍼 포함 총운행시간, 총거리, 기존 대비 차이를 알려줘.

[물류 정보 붙여넣기]
```

기존 라인에서 어느 상차지를 바꾸는지 모호하면 후보별 견적을 나란히 계산한다. 같은 건물의 여러 기업에 각각 전달하면 기업별 작업시간을 더한다. 배송 후 맞수거와 가산 반납도 별도 시간으로 계산한다.

## 팀원: 처음 한 번 준비

### 1. 프로그램 설치

Git, Node.js 22 LTS(22.3 이상, 검증 버전 22.13), [Claude Code](https://code.claude.com/docs/en/quickstart)를 설치한다. 터미널에서 `git --version`, `node --version`, `claude --version`이 실행되는지 확인한다. Claude Code 이용 권한이 있는 본인 계정으로 로그인한다. 계산 스크립트에 별도 LLM API 키가 필요 없다는 뜻이지, Claude Code 서비스 이용이 무료라는 뜻은 아니다.

### 2. 프로젝트 내려받기

터미널(macOS 터미널 또는 Windows PowerShell)에서 순서대로 실행한다. 아래 브랜치에는 팀 견적 도구만 분리되어 있다. 기본 `main`을 받으면 아직 이 도구가 없을 수 있으므로 브랜치 이름을 생략하지 않는다.

```bash
git clone --branch codex/team-quote-sharing --single-branch https://github.com/duckdumplings/onggoing.git onggoing-team-quote
cd onggoing-team-quote
npm ci
```

저장소는 공유 준비 시점 기준 공개 상태라 내려받기에 GitHub 초대나 쓰기 권한이 필요 없다. 회사 정책으로 비공개 전환되면 소유자에게 읽기 권한을 요청한다.

### 3. 접속 설정 넣기

소유자가 비밀정보 공유 도구로 전달한 **팀 견적 전용 `.env.local`**을 방금 내려받은 폴더의 `package.json` 옆에 저장한다. 기존 설정 파일이 있으면 덮어쓰지 말고 담당자와 확인한다. macOS에서는 숨김 파일 표시가 필요할 수 있다. `.env.local.txt`로 저장하지 않는다.

직접 입력하는 경우 [`.env.team-quote.example`](../.env.team-quote.example)을 `.env.local`이라는 이름으로 복사하고 아래 세 항목만 채운다.

| 항목 | 용도 |
|---|---|
| `TMAP_API_KEY` | 주소·도로·교통 조회. 승인된 사용량과 범위의 키 사용 |
| `NEXT_PUBLIC_SUPABASE_URL` | 운임표 프로젝트 주소 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 기존 anon 또는 publishable 공개 접근 키. 운임표 조회는 기존 DB SELECT 권한을 따름 |

`SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_SECRET_KEY`, 관리자 계정, LLM 키는 넣지 않는다. 공개 접근 키 자체가 모든 테이블에 읽기 전용임을 뜻하지는 않는다. 접근 범위는 DB 권한과 RLS가 결정하며, 이 도구는 운임표 SELECT만 수행한다. DB 권한을 넓히거나 관리자 키를 넣어 오류를 우회하지 않는다.

### 4. 확인 후 시작

```bash
# 설치·입력 형식만 확인. 외부 호출과 키 검증은 하지 않음
npm run quote:team -- examples/team-quote.example.json --check

# 위 명령이 성공하면 같은 폴더에서 실행
claude
```

Claude Code 대화창에서 문서 맨 위의 `/ong-quote` 예시와 실제 물류 정보를 입력한다. `/ong-quote`는 터미널 명령어가 아니다. 처음 실제 견적을 실행할 때 교통·운임표 연결까지 확인되며, 보고서의 시간당 운임과 유류 운임 출처가 모두 `database`인지 확인한다. 예측 교통 미확인·기본 운임 사용·마감 위반 경고가 있으면 확정 견적으로 전달하지 않는다.

공개 JSON 예제는 실제 고객정보를 포함하지 않는 가상 주소라 `--check` 전용이다. 실제 조회에는 고객이 준 정확한 주소와 실제 운행일을 사용한다. 현재 검증 환경은 macOS이며 Windows의 전체 계산은 별도 검증 전이다.

## 다음부터 사용하기 / 업데이트

프로젝트 폴더에서 `claude`를 실행하고 `/ong-quote`로 요청하면 된다. 새 버전을 받을 때는 계산 중인 세션을 끝내고 아래 명령을 실행한다.

```bash
git pull --ff-only
npm ci
```

로컬 소스 변경 때문에 업데이트가 막히면 담당자에게 확인한다. `reset --hard`로 지우지 않는다. 고객 입력과 결과는 `quote-runs/`에 둔다.

## 소유자: 설정 파일 전달 준비

승인된 키가 있는 PC의 **이 공유용 브랜치**에서 다음 명령을 실행한다.

```bash
npm run quote:team:export-env
```

현재 로컬 환경에서 필요한 세 항목만 추출해 `quote-runs/team-onboarding/.env.local`에 저장한다. 기존 파일은 덮어쓰지 않는다. 관리자·LLM 키, 고객 데이터, 기타 환경설정은 포함하지 않으며 키 값은 터미널에 출력하지 않는다. macOS/Linux에서는 파일 권한을 소유자 전용으로 설정하며, Windows에서는 OS의 폴더 접근 권한도 확인해야 한다.

이 파일은 Git에 올리지 않는다. 권한을 지정할 수 있는 회사 비밀정보 공유 도구로 해당 팀원에게만 전달한다. 일반 메신저 본문·공개 링크·견적 결과에 붙이지 않는다. Tmap 키는 기존 승인 키를 추출하는 것이며 새 키 발급·사용량 한도 설정·키 회전은 수행하지 않는다. 접근 범위가 맞지 않으면 먼저 공급자에서 팀용 키를 발급받는다. 파일 생성은 전달 준비일 뿐 실제 전달이나 팀원 PC 설정 완료를 의미하지 않는다.

`quote-runs/`에는 고객 주소와 계산 로그도 저장되며 Git에서 제외된다. `--out`을 이 폴더 밖으로 지정하면 Git 제외 보장이 없어지므로 팀 사용에서는 출력 위치를 바꾸지 않는다. 결과 공유 시에는 `.md` 안내문을 확인한 뒤 필요한 사람에게 전달한다. 진단용 `private-server-*.log`는 원문 그대로 공유하지 않는다.

## 막혔을 때

| 증상 | 확인할 것 |
|---|---|
| `claude` 또는 `npm`을 찾을 수 없음 | 설치 후 터미널을 다시 열고 버전 명령 확인 |
| `Missing script: quote:team` | `package.json`이 있는 폴더인지, 공유 브랜치를 받았는지 확인 |
| `/ong-quote`가 보이지 않음 | 해당 폴더에서 새 Claude 세션 시작. `.claude/skills/ong-quote/SKILL.md`를 읽고 진행하도록 요청 |
| Tmap 키 없음 / 도로 조회 실패 | `.env.local` 위치·키 승인 범위·조회 한도 확인. 키 값은 채팅에 붙이지 않음 |
| 운임이 `static-fallback` | 공개 키·연결·운임표 SELECT 권한을 담당자가 확인. 최신 DB 견적으로 단정하지 않음 |
| 설정 내보내기에서 공개키 형식 오류 | 변수 이름만으로 공개키라고 판단하지 않음. 담당자가 실제 anon/publishable 키를 확인하며 관리자 키로 우회하지 않음 |

## 계산 기준

| 항목 | 적용 방식 |
|---|---|
| 기준 날짜 | 명시한 실제 운행일, 한국 시각. 교통 예측이 불가능하면 결과에 표시 |
| 배송 마감 | 차량 도착이 아닌 기업 전달 완료 시각 |
| 조기 배송 | 기본 최대 15분. 고객이 더 짧게 지정하면 그 값을 사용 |
| 안전버퍼 | 기본 20분을 운행·청구 시간에 반영하고, 지연 상황에서도 마감이 지켜지는지 별도 검증 |
| 작업시간 | 상차/반납 기본 10분. 배송은 주차·접근과 기업별 전달, 맞수거 시간을 반영 |
| 동일 주소 여러 기업 | `recipients`별 전달시간을 합산. 기업 수를 배송지 하나로 축소하지 않음 |
| 순서 | 입력한 `stops` 순서를 유지. 다른 순서는 별도 시나리오로 비교 |
| 운임 | 기존 옹라우팅 계산기의 **계산 시점에 유효한 운임표**. 운행일 기준 운임표 선택은 현재 지원하지 않으며, DB 조회 실패 시 참고 견적 표시 |
| 기존 가격 비교 | 부가세 포함 여부를 명시. 불명확하면 확정 증액을 표시하지 않음 |
| 결과 | 부가세 별도 금액, 총거리, 버퍼 포함 운행시간, 청구시간, 타임라인, 마감 및 근거 |

마감 충돌이 있는 라인을 정상 견적으로 포장하지 않는다. 예를 들어 원문 배송 마감이 11:40이면 11:20으로 바꿔 계산하지 않는다. 12:31 맞수거 가능시각이 있으면 배송 직후 바로 출발할 수 있다고 가정하지 않는다. 변경 제안은 원본 결과와 구분한 별도 시나리오로 만든다.

교통은 지정한 운행일로 조회하지만 운임표는 조회 시점 기준이다. 보고서의 운임 근거(`effectiveFrom`, 출처)를 확인한다. 미래 운행일에 요금 변경이 예정되어 있거나 과거 운임을 복원하는 경우에는 이 결과만으로 해당 날짜의 확정 운임이라고 안내하지 않는다.

안전버퍼는 모든 교통·현장 지연에 대한 보증이 아니다. 기사·차량 가용성, 실제 시작 가능일, 가방 크기에 따른 적재 가능 여부는 운영팀에서 확인한다.

## 명령으로 직접 실행하기

아래 날짜는 예시다. 실제 견적에는 반드시 해당 운행일로 바꾼다.

```bash
# 외부 호출 없이 입력 및 기본값 확인
npm run quote:team -- examples/team-quote.example.json --date 2026-10-16 --check

# 실제 조회 및 계산. 필요한 로컬 서버는 자동 시작/종료
npm run quote:team -- quote-runs/request.json --date 2026-10-16

# 결과 이름 지정. 같은 이름의 파일이 있으면 덮어쓰지 않고 중단
npm run quote:team -- quote-runs/request.json --out quote-runs/mapo-friday

# 이미 실행 중인 로컬 앱 사용. 해당 서버는 종료하지 않음
npm run quote:team -- quote-runs/request.json --base-url http://127.0.0.1:3101
```

기본 저장 이름에는 시각과 무작위 식별자가 포함된다. 결과는 다음 세 파일이다.

- `*.input.json`: 적용된 기본값을 포함한 입력 스냅샷
- `*.result.json`: 계산 결과와 검증 근거
- `*.md`: 팀 확인 및 고객 안내에 사용할 문서

`--check`는 키·서버 없이 작동한다. 입력 오류나 계산 실패는 종료코드 1로 끝난다. 계산에 성공했지만 마감이 불가능한 경우에는 그 상태를 포함한 보고서를 정상 저장한다. 실패한 계산은 일부 결과 파일이 비어 있을 수 있으므로 새 출력 이름으로 다시 실행한다.

## JSON 입력 요약

입력 형식 예시는 [`examples/team-quote.example.json`](../examples/team-quote.example.json), 정확한 입력 정의는 [`src/domains/quote/team/input.ts`](../src/domains/quote/team/input.ts)를 참조한다.

| 필드 | 의미 |
|---|---|
| `title`, `serviceDate` | 견적 제목, 운행일 `YYYY-MM-DD` |
| `bufferMinutes`, `earlyMinutes` | 안전버퍼 기본 20분, 최대 조기 배송 기본 15분 |
| `assumptions` | 상차지 변경 대상·차종·작업시간 등 적용 가정 |
| `cases` | 비교할 라인/조건 목록 |
| `cases[].label`, `vehicleType` | 시나리오 이름, `레이` 또는 `스타렉스` |
| `pickupStart` | 첫 상차 **시작**시각 `HH:mm` |
| `scheduleType` | `regular`(정기, 기본) 또는 `ad-hoc`(비정기) |
| `baseline` | 기존 `amount`와 `vat`: `excluded` / `included` / `unknown` |
| `stops` | 방문 순서대로 작업 지점. `role`은 `pickup` / `drop` / `return` |
| `stops[].name`, `address`, `bags` | 지점명, 정확한 주소, 가방 수 |
| `readyAt`, `deadline` | 작업 준비 완료시각, 배송/반납 완료 마감. 배송 마감은 필수 |
| `serviceMinutes` | 전달·주차·접근 전체 작업시간의 직접 지정. 맞수거 시간은 별도 |
| `accessMinutes`, `recipients` | 접근시간과 기업별 `{ name, minutes, bags }`. 기업 전달 기본 4분 |
| `collection` | 맞수거 `{ minutes, readyAt }`. 기본 5분, 수거 가능시각 전에는 대기 |

현재 실행기는 하루 안에 끝나는 경로를 계산한다. 하루를 넘기는 배송은 같은 날 시각으로 억지 변환하지 않는다. 모르는 주소·날짜·마감을 임의로 채우지 말고 필요한 값만 확인한다.
