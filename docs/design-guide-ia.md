# 옹라우팅 정보 구조와 화면 설계

> IA v2 · 2026-08-02

이 문서는 화면 책임과 사용자 흐름만 정의한다. 색상·컴포넌트 계약은 [Design System v2](./design-system.md)를 따른다.

## 1. 핵심 업무 흐름

```text
요청 입력
  → AI 구조화 확인
  → 경로·시간당 운임 계산
  → 예외 우선 검토
  → 조건 수정 또는 견적 저장/PDF 발행
```

AI 대화 세션은 요청 맥락이고, 저장 견적은 재사용 가능한 팀 공용 업무 기록이다. 사용자별 비공개 견적이나
복잡한 승인·버전 상태는 현재 범위에 포함하지 않는다.

## 2. 앱 구조

| 영역 | 책임 |
|---|---|
| Top bar | 현재 작업, 전역 상태, 팀 접근 |
| Start / Command | 새 견적·경로 입력 진입 |
| Workspace tabs | 견적, 경로, 배차의 주요 작업 전환 |
| Quote book | 다중 라인 예외 우선 탐색 |
| Map | 선택 라인의 공간 순서와 위험 구간 |
| Detail pane | 타임라인, 운임 근거, 수정 행동 |
| Saved quotes | 대화와 분리된 팀 공용 견적 불러오기 |

## 3. 견적책 레이아웃

expanded에서는 목록·지도·상세의 3-pane, medium에서는 목록·상세 2-pane, compact에서는 목록과 bottom sheet를 쓴다.
모든 pane은 하나의 `selectedCaseId`를 공유해 같은 라인을 가리켜야 한다.

목록 기본 정렬은 `불가 → 재검토 → 주의 → 정상`. 요약 행에는 전체 타임라인이나 계산 공식을 반복하지 않는다.
상세에는 다음을 한 번씩만 둔다.

- 번호가 있는 실경로 지도와 진행 방향
- 작업 종류, 도착, 체류, 완료, 마감 여유
- 대표 시간당 견적과 유류할증
- 운임표 시행일, 경로 조회 시각, 가정값
- 조건 수정, 같은 조건 재계산, 저장/PDF 발행

## 4. AI 구조화 확인

계산 전에 라인별로 다음 필드를 확인한다.

- 고객/라인명
- 주소와 상차·배송·회수·반납 작업
- 수량과 차량
- 고정 상차, 배송 마감, 시간 범위 등 시각의 의미
- 누락·충돌·모호성

확실한 필드는 한 번에 통과시키고, 문제가 있는 필드만 바로 수정하게 한다. 사용자가 상차 시각을 주지 않아도
배송 마감에서 역산한 권장 상차·출발 시각과 가정을 결과에 표시한다.

## 5. 상태와 피드백

- 빈 상태: 가능한 요청 예시와 첫 행동을 제공한다.
- 로딩: 현재 단계와 유지되는 입력을 보여준다.
- 오류: 문제 필드와 복구 행동을 연결한다.
- 부분 성공: 계산된 라인은 유지하고 실패 라인만 재검토한다.
- 완료: 저장·PDF·조건 수정 중 다음 행동을 명확히 한다.

상태는 색상만으로 구분하지 않는다. `지각 예상`, `주소 확인 필요`, `마감 여유 18분`처럼 원인과 수치를 쓴다.

## 6. 데이터와 보안 경계

- 로그인 없는 견적 대화는 가능하지만 파일 업로드·파싱·검토 기록은 인증된 팀 API를 통한다.
- 저장 견적은 팀 공용이며 브라우저에서 테이블을 직접 수정하지 않는다.
- LLM 요청은 서버 지정 모델, 요청 크기, burst rate limit을 적용한다.
- 원본 문서 Storage는 private이며 다운로드는 만료되는 서명 URL을 사용한다.

## 7. 구현 위치

- 공통 primitive: `src/components/ui/`
- 견적 도메인: `src/domains/quote/`
- 견적책/배송: `src/domains/dispatch/`
- API route는 인증·입력 검증·응답 조립만 담당하고, 계산은 domain service로 분리한다.

## 8. 화면 변경 완료 조건

- desktop/compact 실제 브라우저 검증
- 입력·로딩·오류·빈 상태·다중 라인 확인
- 선택 라인과 지도·타임라인 동기화 확인
- 접근성 이름과 keyboard focus 확인
- 디자인 lint, 타입 검사, 관련 테스트 통과
